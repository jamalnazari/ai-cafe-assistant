# معماری پروژه

## نمای کلی

```text
مرورگر مشتری/مالک
        │  HTTPS
        ▼
      Caddy  ── /api/* ──►  FastAPI (127.0.0.1:8000)  ──►  SQLite
        │                          │
        └── بقیه ──────────►  Next.js (127.0.0.1:3000)
```

- **Next.js** فقط رابط کاربری و اعتبارسنجی نشست سمت سرور را انجام می‌دهد.
- **FastAPI** تنها جایی است که منطق کسب‌وکار، دیتابیس و کلیدهای هوش مصنوعی وجود دارد.
- **SQLite** با فعال‌سازی WAL و `busy_timeout` برای ترافیک یک کافه کافی است.

## لایه‌های بک‌اند

| لایه | مسیر | مسئولیت |
| --- | --- | --- |
| API | `main.py` | تعریف مسیرها، اعتبارسنجی ورودی، کدهای خطا |
| Core | `app/core/` | تنظیمات، امنیت، احراز هویت، محدودیت نرخ |
| Models | `app/models/` | جدول‌های SQLAlchemy |
| Schemas | `app/schemas/` | قراردادهای ورودی/خروجی Pydantic |
| Repositories | `app/repositories/` | کوئری‌های دیتابیس |
| Services | `app/services/` | منطق دستیار، تصاویر، پیشنهاد آیتم |
| Providers | `app/providers/` | آداپتور LLM و STT (mock یا OpenAI-compatible) |

## تصمیم‌های مهم

1. **تک‌کافه (single-tenant):** slug کافه `demo` است. برای چندکافه‌ای شدن باید
   `restaurant_slug` از مسیر/تنظیمات خوانده شود و همهٔ کوئری‌ها فیلتر رستوران داشته باشند.
2. **پاسخ فقط از دادهٔ منو:** پرامپت سیستم، مدل را به دادهٔ منو محدود می‌کند و
   آیتم‌های نام‌برده‌شده با `find_mentioned_items` از دیتابیس استخراج می‌شوند تا مدل
   نتواند آیتم خیالی بسازد.
3. **قیمت به ریال، نمایش به تومان:** ذخیره‌سازی در `price_amount` با واحد ریال انجام
   می‌شود و تبدیل در لایهٔ نمایش است.
4. **آلرژن سه‌حالته:** `null` یعنی «بررسی نشده»، `[]` یعنی «بررسی شده و بدون آلرژن».
5. **احراز هویت با کوکی نشست:** رمز با Argon2 هش می‌شود، توکن تصادفی در کوکی
   `HttpOnly` قرار می‌گیرد و هش آن در جدول `auth_sessions` نگه‌داری می‌شود تا امکان
   ابطال نشست وجود داشته باشد.
6. **محدودیت نرخ درون‌حافظه‌ای:** برای تک‌پروسهٔ uvicorn کافی است؛ در مقیاس چندسروری
   باید به Redis منتقل شود.
7. **پیکربندی امن در production:** بدون `SECRET_KEY` معتبر سرویس بالا نمی‌آید،
   مستندات API بسته است و سرویس‌ها فقط روی loopback گوش می‌دهند.

## جریان پرسش مشتری

```text
POST /api/v1/restaurants/demo/ask-text
  ├─ محدودیت نرخ بر اساس IP
  ├─ بارگذاری منو از دیتابیس
  ├─ ساخت پرامپت از منو + ۶ نوبت اخیر گفتگو
  ├─ فراخوانی سرویس LLM با تلاش دوباره در خطاهای موقت
  └─ پاسخ + آیتم‌های پیشنهادی (استخراج‌شده از دیتابیس)
```

در صورت خطای سرویس هوش مصنوعی، پاسخ `503` با پیام فارسی برگردانده می‌شود و
رابط کاربری همان پیام را نمایش می‌دهد.

| POST | `/api/v1/auth/login` | عمومی (با محدودیت نرخ) |
| GET | `/api/v1/auth/me` | مالک |
| POST | `/api/v1/auth/logout` | عمومی |
| GET | `/api/v1/restaurants/{slug}/menu` | عمومی |
| POST | `/api/v1/restaurants/{slug}/categories` | مالک |
| DELETE | `/api/v1/restaurants/{slug}/categories/{name}` | مالک |
| POST/PATCH/DELETE | `/api/v1/restaurants/{slug}/items...` | مالک |
| POST | `/api/v1/restaurants/{slug}/ask-text` | عمومی (با محدودیت نرخ) |
| POST | `/api/v1/restaurants/{slug}/ask-voice` | عمومی (با محدودیت نرخ) |
| GET | `/health` | عمومی |

## وضعیت و گام‌های بعدی

- گفت‌وگوی صوتی در رابط مشتری هنوز فعال نیست (مسیرها آماده‌اند).
- برای نسخه‌های چندکافه‌ای: مهاجرت از `init_db` دستی به Alembic و افزودن
  مدیریت چند کاربر.

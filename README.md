# کافه‌یار — دستیار هوشمند منوی کافه

منوی دیجیتال فارسی برای کافه و رستوران با دستیار پاسخ‌گوی هوش مصنوعی.
مشتری با اسکن QR روی میز، منو را در مرورگر می‌بیند، دسته‌بندی دلخواهش را انتخاب می‌کند
و دربارهٔ غذاها و نوشیدنی‌ها سؤال می‌پرسد. صاحب کافه منو را از پنل مدیریت می‌کند.

این نسخه **تک‌کافه** (single-tenant) است: یک کافه با slug ثابت `demo`.

## قابلیت‌ها

### تجربهٔ مشتری

- **بدون نصب اپلیکیشن:** اسکن QR → باز شدن صفحه در مرورگر موبایل.
- **منوی دسته‌بندی‌شده:** نوار چسبان دسته‌بندی با گزینهٔ «همه موارد» و تعداد آیتم‌های
  هر دسته؛ با اسکرول، دستهٔ فعال به‌صورت خودکار مشخص می‌شود.
- **جزئیات آیتم:** مواد اولیه، آلرژن‌ها، دمای سرو، توضیحات و تصویر در مودال؛
  قیمت در دیتابیس به ریال ذخیره و در رابط کاربری به تومان نمایش داده می‌شود.
- **دستیار متنی:** پرسش و پاسخ فارسی بر پایهٔ منوی همان کافه، با حفظ زمینهٔ گفتگو
  (تا ۶ نوبت اخیر) و نمایش خودکار آیتم‌هایی که در پاسخ به آن‌ها اشاره شده است.
- **هویت بصری کافه:** لوگوی کافه و تصویر پس‌زمینهٔ انتخابی صاحب کافه در سرصفحه و
  پس‌زمینهٔ صفحهٔ مشتری نمایش داده می‌شود.
- **دربارهٔ مجموعه:** توضیحات کلی کافه (ساعت کاری، آدرس، فضا، پارکینگ و…) که صاحب
  کافه در پنل می‌نویسد، در پرامپت دستیار قرار می‌گیرد و پاسخ پرسش‌های عمومی از همان
  متن داده می‌شود؛ اگر مطلبی ثبت نشده باشد، دستیار حدس نمی‌زند.
- **چهار تم ظاهری:** کهربایی (پیش‌فرض)، بنفش، نعنایی و شبانه؛ انتخاب کاربر در
  `localStorage` ذخیره می‌شود.
- راست‌به‌چپ کامل با فونت **وزیرمتن** که به‌صورت محلی همراه پروژه توزیع می‌شود
  (بدون وابستگی به Google Fonts در زمان اجرا).

### تجربهٔ صاحب کافه

- ورود امن با کوکی نشست (`HttpOnly`) و اعتبارسنجی سمت سرور.
- تغییر **نام کافه**، بارگذاری **لوگو** و **تصویر پس‌زمینهٔ صفحهٔ مشتری** از پنل.
- نوشتن و ویرایش **دربارهٔ مجموعه** در پنل (تا ۱۵۰۰ نویسه) برای استفادهٔ دستیار.
- پنل روی موبایل هم کامل کار می‌کند: تب «منو / مدیریت کافه»، مودال‌های کشویی و دکمهٔ
  شناور افزودن آیتم.
- افزودن، ویرایش و حذف آیتم‌های منو؛ تعیین دسته، قیمت، مواد اولیه، آلرژن و دمای سرو.
- افزودن دسته‌بندی جدید و حذف دسته‌های خالی
  (دستهٔ دارای آیتم حذف نمی‌شود تا محصولات ناخواسته از بین نروند).
- بارگذاری تصویر برای هر آیتم (JPG/PNG/WebP تا ۵ مگابایت).
- تولید QR و لینک مستقیم منوی مشتری.
- تغییر تم از داخل پنل.

## راه‌اندازی سریع

### ۱) بک‌اند

**Windows (PowerShell یا CMD):**

```bat
cd apps\api
python -m venv .venv
.venv\Scripts\python.exe -m pip install --upgrade pip
.venv\Scripts\python.exe -m pip install -r requirements.txt
.venv\Scripts\python.exe -m app.db.init_db
```

**macOS / Linux:**

```bash
cd apps/api
python3 -m venv .venv
.venv/bin/pip install -r requirements.txt
.venv/bin/python -m app.db.init_db
```

### ۲) فایل تنظیمات

یک فایل `apps/api/.env` بسازید (مثال در `.env.example` ریشه):

```env
DATABASE_URL=sqlite+aiosqlite:///./cafe.db
SECRET_KEY=یک-رشته-تصادفی-بلند-و-یکتا
STT_PROVIDER=mock
LLM_PROVIDER=mock
AI_BASE_URL=https://api.openai.com/v1
AI_API_KEY=mock-key
STT_MODEL=whisper-1
LLM_MODEL=gpt-4o-mini
SESSION_COOKIE_NAME=cafe_owner_session
SESSION_TTL_SECONDS=604800
SESSION_COOKIE_SECURE=False
```

### ۳) فرانت‌اند

```bat
cd apps\web
npm install
```

### ۴) اجرای پروژه

از **ریشهٔ پروژه**:

```bat
npm start
```

این دستور هر دو سرویس را بالا می‌آورد:

- رابط کاربری: <http://localhost:3000>
- API و مستندات: <http://localhost:8000/docs>

با `Ctrl + C` هر دو سرویس خاموش می‌شوند. اگر پوشهٔ `.venv` یا
`apps/web/node_modules` وجود نداشته باشد، اسکریپت با پیام فارسی متوقف می‌شود.

## تنظیمات محیطی

| متغیر | پیش‌فرض | توضیح |
| --- | --- | --- |
| `ENVIRONMENT` | `development` | `development` یا `production` |
| `DATABASE_URL` | `sqlite+aiosqlite:///./cafe.db` | مسیر دیتابیس؛ نسبت به پوشهٔ `apps/api` |
| `SECRET_KEY` | مقدار توسعه | امضای کوکی نشست — **در production حداقل ۳۲ نویسه و الزامی** |
| `SESSION_COOKIE_NAME` | `cafe_owner_session` | نام کوکی نشست مالک |
| `SESSION_TTL_SECONDS` | `604800` | مدت اعتبار نشست (۷ روز) |
| `SESSION_COOKIE_SECURE` | خودکار | خالی بماند: در production `True` و در توسعه `False` |
| `RATE_LIMIT_ENABLED` | `True` | فعال بودن محدودیت نرخ |
| `ASK_RATE_LIMIT` / `ASK_RATE_WINDOW_SECONDS` | `20` / `60` | سقف پرسش هر IP در هر بازه |
| `LOGIN_RATE_LIMIT` / `LOGIN_RATE_WINDOW_SECONDS` | `8` / `300` | سقف تلاش ورود هر IP |
| `TRUST_PROXY_HEADERS` | `False` | پشت Caddy/Nginx مقدار `True` |
| `ALLOWED_HOSTS` | خالی | دامنه‌های مجاز، جداشده با کاما |
| `UPLOAD_DIR` | `apps/api/uploads/menu_items` | پوشهٔ تصاویر؛ در سرور بیرون از پروژه بگذارید |
| `BACKUP_DIR` / `BACKUP_KEEP` | `apps/api/backups` / `14` | مقصد و تعداد نسخه‌های پشتیبان |
| `AI_REQUEST_TIMEOUT_SECONDS` / `AI_MAX_RETRIES` | `30` / `2` | زمان انتظار و تلاش دوبارهٔ LLM |
| `LLM_PROVIDER` | `mock` | `mock` یا `openai` (سازگار با OpenAI) |
| `AI_BASE_URL` | `https://api.openai.com/v1` | آدرس پایهٔ سرویس، تا انتهای `/v1` |
| `AI_API_KEY` | `mock-key` | کلید سرویس — فقط در بک‌اند |
| `LLM_MODEL` | `gpt-4o-mini` | شناسهٔ مدل |
| `STT_PROVIDER` | `mock` | `mock` یا `openai` (برای مسیر صوتی آینده) |
| `STT_MODEL` | `whisper-1` | مدل تبدیل گفتار به متن |
| `UPLOAD_DIR` | `apps/api/uploads/menu_items` | پوشهٔ تصاویر بارگذاری‌شده |
| `API_INTERNAL_URL` | `http://127.0.0.1:8000` | فقط برای Next.js (سمت سرور) |

محل خواندن فایل‌ها:

- بک‌اند: `apps/api/.env` **یا** `.env` در ریشهٔ پروژه (اولویت با اولی است —
  چون `env_file` چندتایی است، دومی مقدار اولی را بازنویسی می‌کند).
- فرانت‌اند: `apps/web/.env.local` (برای تغییر `API_INTERNAL_URL`).

## اتصال به سرویس هوش مصنوعی

به‌صورت پیش‌فرض همه‌چیز با `mock` کار می‌کند: بدون هزینه و بدون کلید، پاسخ‌ها
قالب‌بندی‌شده و قابل تست هستند.

برای اتصال به یک سرویس واقعی سازگار با OpenAI (OpenAI، Routeway، Dahl و مانند آن):

```env
LLM_PROVIDER=openai
AI_BASE_URL=https://api.routeway.ai/v1
AI_API_KEY=کلید-واقعی-شما
LLM_MODEL=muse-glimmer-30b:free
```

نکته‌ها:

- `AI_BASE_URL` را تا انتهای `/v1` بنویسید؛ مسیر `/chat/completions` خودکار اضافه می‌شود.
- `LLM_MODEL` باید **دقیقاً** همان شناسهٔ اعلام‌شده توسط سرویس‌دهنده باشد.
- کلید API فقط در بک‌اند خوانده می‌شود و هرگز به مرورگر نمی‌رود.
- دستیار فقط از دادهٔ منوی همان کافه پاسخ می‌دهد؛ اگر اطلاعاتی در منو نباشد،
  از خودش چیزی نمی‌سازد و مشتری را به پرسیدن از کارکنان راهنمایی می‌کند.

## دادهٔ نمونه و تصاویر

```bat
cd apps\api
.venv\Scripts\python.exe -m app.db.seed_demo_menu
```

این اسکریپت idempotent است و ۲۴ آیتم در ۵ دسته‌بندی (غذای ایرانی، فست‌فود،
نوشیدنی سرد، نوشیدنی گرم، دسر) می‌سازد، ستون‌های جدید را با `init_db` اضافه می‌کند
و تصاویر را از `app/data/menu_images` به پوشهٔ `uploads/menu_items` کپی می‌کند.

منبع و مجوز تصاویر در `apps/api/app/data/menu_images/ATTRIBUTION.md` آمده است.

## دستورهای توسعه

همهٔ دستورها از **ریشهٔ پروژه** اجرا می‌شوند:

| کار | دستور |
| --- | --- |
| اجرای توسعه (هر دو سرویس) | `npm start` |
| اجرای تولیدی (بیلد + اجرا) | `npm run start:prod` |
| بیلد فرانت‌اند | `npm run build` |
| تست بک‌اند | `npm test` |
| لینت فرانت‌اند | `npm run lint` |
| ساخت/به‌روزرسانی دیتابیس | `npm run db:init` |
| منوی نمونه با تصاویر | `npm run db:seed` |
| پشتیبان‌گیری از دیتابیس | `npm run db:backup` |
| تغییر رمز صاحب کافه | `npm run owner:password` |
| بررسی تنظیمات پیش از استقرار | `ENVIRONMENT=production npm run check:prod` |

تست‌ها از دیتابیس موقت استفاده می‌کنند و به `cafe.db` شما دست نمی‌زنند.

## اجرای تولیدی

```bash
npm run build
ENVIRONMENT=production npm run check:prod   # صحت SECRET_KEY و کلیدها
ENVIRONMENT=production npm run start:prod
```

در حالت production:

- مستندات تعاملی API (`/docs` و `/openapi.json`) بسته است.
- سرویس‌ها فقط روی `127.0.0.1` گوش می‌دهند؛ ترافیک از پروکسی (Caddy/Nginx) می‌آید.
- کوکی نشست به‌صورت خودکار `Secure` می‌شود.
- بدون `SECRET_KEY` معتبر سرویس بالا نمی‌آید.
- `/health` سلامت دیتابیس را هم بررسی می‌کند.

راهنمای کامل استقرار (systemd، HTTPS، پشتیبان‌گیری، چک‌لیست امنیتی):
**[docs/DEPLOY.md](docs/DEPLOY.md)**

## نکات امنیتی

- فایل `.env` و کلیدهای API را هرگز commit نکنید (در `.gitignore` هست).
- `SECRET_KEY` پیش‌فرض فقط برای توسعه است؛ در production سرویس با آن بالا نمی‌آید.
- روی HTTPS کوکی نشست خودکار `Secure` می‌شود؛ در حالت دستی مقدار `True` بگذارید.
- رمز پیش‌فرض مالک (`123456`) را با `npm run owner:password` تغییر دهید؛
  در production هنگام راه‌اندازی هشدار داده می‌شود.
- محدودیت نرخ روی `/login` و `/ask-text` فعال است (پاسخ `429` با پیام فارسی).
- پورت‌های ۸۰۰۰ و ۳۰۰۰ را از بیرون نبندید؛ فقط ۸۰/۴۴۳ باز باشد.
- پشتیبان روزانه با `npm run db:backup` و تصاویر منو جداگانه بگیرید.
- پوشهٔ `apps/api/uploads/` در گیت نادیده گرفته می‌شود.

## عیب‌یابی

| مشکل | علت و راه‌حل |
| --- | --- |
| `Python virtual environment not found` | `apps/api/.venv` نساخته‌اید؛ مرحلهٔ ۱ را انجام دهید |
| `Next.js is not installed` | `cd apps/web && npm install` |
| پورت ۳۰۰۰ یا ۸۰۰۰ اشغال است | سرویس دیگری را ببندید یا پورت را در `scripts/start-project.mjs` تغییر دهید |
| پنل، منو را خالی نشان می‌دهد | `python -m app.db.seed_demo_menu` را اجرا کنید |
| تغییر `API_INTERNAL_URL` اثر ندارد | این متغیر را در `apps/web/.env.local` بگذارید، نه ریشهٔ پروژه |
| پاسخ `429` برای مشتری | محدودیت نرخ فعال است؛ `ASK_RATE_LIMIT` را تنظیم کنید |
| «دستیار موقتاً در دسترس نیست» (۵۰۳) | سرویس هوش مصنوعی قطع/کند است؛ کلید و مدل را بررسی کنید |
| سرویس در production بالا نمی‌آید | خروجی `npm run check:prod` را ببینید (اغلب `SECRET_KEY`) |
| پاسخ دستیار خطای ۴۰۱ می‌دهد | `AI_BASE_URL`/`AI_API_KEY`/`LLM_MODEL` با سرویس‌دهنده هم‌خوان نیست |

## محدودهٔ فعلی

**انجام‌شده:** منوی دیجیتال، دسته‌بندی، پنل مالک با احراز هویت، CRUD آیتم‌ها،
تصاویر، QR، دستیار متنی با زمینهٔ گفتگو، چهار تم، اجرای یکپارچه، و آماده‌سازی
استقرار: اجرای تولیدی، محدودیت نرخ، مدیریت خطای LLM، `/health` واقعی،
پشتیبان‌گیری، HTTPS با Caddy و CI.

**در محدودهٔ نسخه‌های بعدی:**

- گفت‌وگوی صوتی در رابط مشتری (مسیر `/ask-voice` در بک‌اند آماده است،
  رابط کاربری فعلاً فقط متنی است)
- پشتیبانی چندکافه (multi-tenant) به‌جای slug ثابت `demo`
- سفارش‌گیری و پرداخت، رزرو میز، اتصال به صندوق فروش

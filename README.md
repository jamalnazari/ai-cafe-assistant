# دستیار صوتی منوی رستوران

## معرفی

یک وب‌اپلیکیشن برای رستوران‌ها که به مشتری اجازه می‌دهد QR code روی میز را اسکن کند و با کمک دستیار صوتی دربارهٔ منو سؤال بپرسد.

صاحب رستوران در پنل خود اطلاعات منو را مدیریت می‌کند. دستیار باید پاسخ‌هایش را فقط بر اساس اطلاعات همان منو ارائه دهد.

## هدف پروژه

ساخت یک پایلوت کوچک برای بررسی دو موضوع:

- آیا مشتری‌ها دوست دارند دربارهٔ غذاها با صدا سؤال بپرسند؟
- آیا رستوران‌ها حاضرند برای این قابلیت از محصول استفاده کنند؟

## جریان اصلی مشتری

1. مشتری QR code رستوران یا میز را اسکن می‌کند.
2. صفحهٔ رستوران در مرورگر باز می‌شود.
3. مشتری دکمهٔ «شروع مکالمه» را می‌زند.
4. دستیار صوتی خوشامدگویی می‌کند.
5. مشتری دربارهٔ منو سؤال می‌پرسد.
6. پاسخ دستیار به‌صورت متنی و صوتی نمایش داده و پخش می‌شود.

شروع مکالمه با لمس دکمه است؛ پخش خودکار صدا ممکن است توسط مرورگر مسدود شود. اگر اطلاعاتی در منو ثبت نشده باشد، دستیار نباید حدس بزند و باید مشتری را به پرسیدن از کارکنان راهنمایی کند.

## محدودهٔ نسخهٔ اولیه

### مرحلهٔ اول: نمونهٔ فنی

- یک رستوران آزمایشی
- یک منوی نمونه
- بررسی امکان پرسش و پاسخ صوتی فارسی در مرورگر
- پاسخ متنی در کنار پاسخ صوتی

### مرحلهٔ دوم: پایلوت MVP

- ورود و ویرایش اطلاعات منو توسط صاحب رستوران
- نمایش منوی مرتبط با QR اسکن‌شده
- پرسش و پاسخ صوتی دربارهٔ منو
- جلوگیری از نمایش اطلاعات یک رستوران به رستوران دیگر

### خارج از محدودهٔ نسخهٔ اولیه

- سفارش‌گیری و پرداخت
- اتصال به نرم‌افزارهای صندوق رستوران
- رزرو میز
- گفت‌وگوی صوتی زنده و پیوسته
- اپلیکیشن موبایل مستقل

## فناوری‌های پیشنهادی

- Frontend: React, JavaScript, Tailwind CSS
- Backend: Python, FastAPI
- دیتابیس و سرویس‌های صوتی هنوز انتخاب نشده‌اند و پیش از انتخاب بررسی می‌شوند.

## اصول مهم

- اطلاعات منو منبع اصلی پاسخ‌هاست؛ دستیار نباید دربارهٔ غذا، قیمت یا آلرژن‌ها حدس بزند.
- کلیدهای API فقط در backend نگهداری می‌شوند.
- اطلاعات مشتری تا حد امکان جمع‌آوری یا ذخیره نمی‌شود.
- انتخاب سرویس‌دهنده و تصمیم‌های معماری در مستندات پروژه ثبت می‌شوند.

## وضعیت پروژه

در حال برنامه‌ریزی؛ هنوز پیاده‌سازی برنامه شروع نشده است.
